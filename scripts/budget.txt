# What each benchmark may spend.
#
#   <package> <benchmark> <allocs/op> <B/op>
#
# scripts/bench.sh runs the suite and fails if any benchmark allocates more
# times than its budget, or more than a shade over its budget in bytes. Every
# benchmark must appear here and every line here must name a benchmark that
# runs, so that neither a new measurement nor a deleted one can slip past
# unread. A figure that falls below half its budget fails as well: something
# spending far less than it used to has usually stopped doing the work.
#
# Changing a number is the point, not a failure of the process: a budget that
# goes up should be a line in a review with a reason beside it, and one that
# goes down is somebody's work showing.
#
# Measured on go1.27 for a 64-bit word, which is what every build in the matrix
# is. Allocation counts are the same everywhere; the byte figures count two
# words per string header and one per pointer.

# The generated container, and the same work written by hand beside it.
#
# The generated forms all cost more than the hand-written ones, and all for one
# reason: the helpers underneath them require only that the stack beneath can
# be walked, so they grow their result rather than sizing it ahead. Walking is
# all a projection needs, and a storage that cannot report a length without
# walking itself is a storage a collection should still work over.
#
# That is the contract and not the last word on it. A stack that *can* report
# its length says so — the slice storage reports Sized — and the collection
# layer is handed the shape beneath it before it generates anything, so a
# variant that sizes its result ahead when the length is free is available and
# is not written yet. These figures are what it would be measured against.

# The generated JSON codec over a thousand elements, and the reflective encoder
# over the same elements beside it. Every one of these is warmed before it is
# measured: an encoder grows its buffer once to fit the largest document it has
# written, and a figure that included that growth would report it divided by
# however many iterations the run happened to do.
#
# What the pairs say, measured rather than assumed, is that the win is not where
# the project first expected it. Writing costs nothing at all — no allocation
# for a thousand elements, against two for the reflective path — and takes about
# a quarter longer, because encoding/json/v2 writes a struct straight into its
# buffer while a generated codec goes through the token API a caller could have
# used themselves. Reading is the other way round: the same allocations, since
# both make the same strings, and about a sixth quicker.
#
# So the encoder's claim is memory and the decoder's is time, and neither is the
# order-of-magnitude the pre-v2 generators had. That is the caveat prd.md §14
# opens with, now with numbers under it. The reflective figures are held to a
# budget too, because a baseline that quietly stopped doing the work would make
# the comparison meaningless while leaving both lines green.

# The generated check over a value that satisfies its rules, which is the path
# a check spends its life on: validation runs on every request and almost always
# finds nothing.
#
# Zero is the figure that matters and the one the whole layer is for. The two
# hand-written versions beside it are what say where the time goes, and they
# have to be read together: against the scan the generated check looks an order
# of magnitude slower, and almost all of that is the regexp engine the tag asked
# for; against the same pattern, what is left is what generation costs, which is
# within the noise of writing it out by hand.
#
# So a rule set with a pattern in it is a rule set whose cost is the pattern.
# The comparison against go-playground/validator lives in its own module — see
# scripts/budget-against.txt — and says the same thing from the other side.
