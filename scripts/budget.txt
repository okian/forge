# What each benchmark may spend.
#
#   <package> <benchmark> <allocs/op> <B/op>
#
# scripts/bench.sh runs the suite and fails if any benchmark allocates more
# times than its budget, or more than a shade over its budget in bytes. Every
# benchmark must appear here and every line here must name a benchmark that
# runs, so that neither a new measurement nor a deleted one can slip past
# unread. A figure that falls below half its budget fails as well: something
# spending far less than it used to has usually stopped doing the work.
#
# Changing a number is the point, not a failure of the process: a budget that
# goes up should be a line in a review with a reason beside it, and one that
# goes down is somebody's work showing.
#
# Measured on go1.27 for a 64-bit word, which is what every build in the matrix
# is. Allocation counts are the same everywhere; the byte figures count two
# words per string header and one per pointer.

# The generated container, and the same work written by hand beside it.
#
# The generated forms all cost more than the hand-written ones, and all for one
# reason: the helpers underneath them require only that the stack beneath can
# be walked, so they grow their result rather than sizing it ahead. Walking is
# all a projection needs, and a storage that cannot report a length without
# walking itself is a storage a collection should still work over.
#
# The figures moved when the subject gained a slice: a Person is a slice header
# wider than it was, so every collection that holds one of each element is wider
# by that much per element. Written down rather than raised to fit, because a
# budget that moved on its own would be a budget about nothing.
#
# That is the contract and not the last word on it. A stack that *can* report
# its length says so — the slice storage reports Sized — and the collection
# layer is handed the shape beneath it before it generates anything, so a
# variant that sizes its result ahead when the length is free is available and
# is not written yet. These figures are what it would be measured against.

# The keyed storage against the same pair of structures written by hand, over
# a thousand people. The reads are the point and are free: the primary lookup
# answers a pointer with no allocation and beats the hand-written value map,
# which copies the struct out; the secondary walks the one percent sharing a
# name in a twentieth of the scan's time, nothing allocated either way.
#
# Building pays for the pointer stability. One entry allocation per element is
# what lets a lookup's answer survive its neighbours' removal, and the maps
# are made on first use by the same bodies that serve the zero value, so the
# constructor cannot size them ahead the way the by-hand loop does. Churn is
# an add and a removal per operation: the generated pair costs one entry and
# the sequence wrapping the element; the hand-written one, appending into a
# bucket it just emptied, one.

# The generated JSON codec over a thousand elements, and the reflective encoder
# over the same elements beside it. Every one of these is warmed before it is
# measured: a buffer grows once to fit the largest document it has written, and
# a figure that included that growth would report it divided by however many
# iterations the run happened to do.
#
# The codec appends bytes and scans them rather than driving the standard
# library's token machinery, and the pairs say what that buys. Writing a
# thousand elements allocates nothing and takes about a quarter of the
# reflective time. Reading allocates what the strings cost — the same two

# pointing into the document instead of copying out of it is for. WriteTo

#

# leaving both lines green.

# The generated check over a value that satisfies its rules, which is the path
# a check spends its life on: validation runs on every request and almost always
# finds nothing.
#
# Zero is the figure that matters and the one the whole layer is for. The two
# hand-written versions beside it are what say where the time goes, and they
# have to be read together: against the scan the generated check looks an order
# of magnitude slower, and almost all of that is the regexp engine the tag asked
# for; against the same pattern, what is left is what generation costs, which is
# within the noise of writing it out by hand.
#
# So a rule set with a pattern in it is a rule set whose cost is the pattern.
# The comparison against go-playground/validator lives in its own module — see
# scripts/budget-against.txt — and says the same thing from the other side.
# The one byte on the pattern rows is regexp's own: MatchString borrows a
# machine from an internal pool, and the pool's rare refill amortizes to a
# byte per operation at this run length — zero allocations, one accounted
# byte. Generated and by-hand carry it alike, which is the comparison holding.

# The lock, and the same work under a mutex somebody wrote by hand.
#
# Nothing allocates on either side of the pair, which is the claim: a lock that
# allocated would be a lock nobody could put on a hot path, and the arrangement
# that makes the unlocked methods unreachable — a view built and handed to a
# closure — is arranged so that it costs nothing to build.
#
# What the timings say, which nothing here gates, is that a count costs what a
# hand-written one costs (3.6ns against 3.5ns on an M3, so the difference is the
# measurement) and a write scope costs about five nanoseconds more (11.4 against
# 6.5). Those five are the closure and the view, and they are what a caller pays
# for not being able to reach the container without taking the lock. Written
# down because "overhead ≈ 0" is true of one of the two and not of the other,
# and the half it is not true of is the half worth knowing about.

# The copy a guarded stack hands out, and the document written from one.
#
# One allocation, which is the copy itself: the container is asked how much it
# holds before the walk starts, so the slice is made once at the right size
# rather than grown as it goes. It was seven allocations and ten kilobytes when
# this benchmark was first written — a doubling per growth, copying what it had
# each time — and the figure is here so that it cannot quietly go back.
#
# The encode is the same one allocation, so the copy is the whole of what
# encoding a guarded container costs over encoding an unguarded one. That is the
# bargain the layer's default makes: one copy of the elements per document, in
# exchange for never holding the lock against every writer for as long as the
# caller's writer takes to accept the bytes.

# Deriving a name, which every generated identifier is paid for once.
#
# One allocation for a plural of either kind, which is the claim the dictionary
# had to earn: consulting a real English dictionary must not cost more than the
# three suffix rules it replaced. Two things buy it. Every lookup folds the word
# as it compares rather than lower-casing a copy of it first, and a hit answers
# with a slice of the asset rather than a copy of the word it found — so the one
# allocation left is the answer itself, which the caller was always going to get
# a string of.
#
# A compound name pays a second, which is the join: only the last word inflects
# and HomeAddress has to be put back together around Addresses.
#
# Spelling a name out of its parts is the eight, and they are the words: a
# builder growing, and one raised first letter each. Written down rather than
# tuned, because it is paid once per declaration rather than once per element,
# and because the number is here to notice a change rather than to be admired.
#
# The dictionary is decoded once per process and only if something asks, so
# every one of these warms it before it measures. A run that did not would
# divide one decode by however many iterations it did and report a number about
# the run length.
